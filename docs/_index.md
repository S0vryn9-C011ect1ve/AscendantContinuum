## Documentation Domains

- `docs/design/`: game design, realm design, progression systems
- `docs/technical/`: architecture, API, build/deploy, technical setup
- `docs/security/`: security policy and supply-chain protections
- `docs/social/`: social automation and publishing operations

- `docs/standards/`: repository, naming, and asset standards

## Rules

- Prefer canonical docs over legacy root markdown files.
- Add new docs to a domain folder, not the repository root.
- Archive and delete only after wave-gated verification.
- Use historical context docs as reference only; they do not override active standards.
