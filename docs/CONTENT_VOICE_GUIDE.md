# Content Voice Guide: Solo Dev Learning Journey

## Core Philosophy
**Learning Unity while building a game. Sharing what works.**

Authentic, collaborative, helpful. Not an expert teaching - a developer learning and sharing discoveries.

## Voice Characteristics

### ✅ DO Use:
- "Here's what I learned about..."
- "I figured out a way to..."
- "After trying [X], this approach worked..."
- "Learning [feature] as I build - here's what clicked..."
- "This pattern made [concept] finally make sense..."
- "Spent [time] on this, here's what worked..."
- "I'm using [approach] for [feature] - working well so far..."

### ❌ DON'T Use:
- "Nobody explains this properly..."
- "The docs are terrible..."
- "Most games do X wrong..."
- "We built a sophisticated system..."
- "Players have reported..."
- "Steal this system..."

## Tone Examples

### Before (Confrontational):
> "Firebase + Unity: the integration nobody explains properly"

### After (Helpful):
> "Here's how I got Firebase + Unity integration working"

### Before (Expert):
> "Most games add accessibility as an option. We made it a feature."

### After (Learning):
> "Learning how colorblind modes work - found you can make them reveal different content"

### Before (Authority):
> "Steal this Unity system for your game"

### After (Sharing):
> "This ScriptableObject pattern helped me organize game state"

### Before (Confrontational):
> "Unity tutorials teach this wrong"

### After (Constructive):
> "I tried the common approach, but this worked better for my use case"

## Content Structure

### Social Media Posts
**Hook Pattern:** [What I'm learning] + [What worked]
- "Here's how I got Addressables working for asset streaming"
- "Found a pattern for ScriptableObjects that finally clicked"
- "Learning Firebase security rules - this approach helped"

**Body Pattern:** Practical results, specific improvements
- "Tried a few approaches, this one worked best"
- "Reduced build size from 1.2GB to 85MB using Addressables"
- "Hired a contractor for art ($2,400) - saved tons of time"

### Blog Posts
**Hook Pattern:** Learning question or discovery
- "Learning mobile optimization in Unity - here's what helped"
- "I spent a while figuring out Firebase integration - here's my approach"

**Content Pattern:**
1. What I was trying to build
2. First approach and what I learned
3. What adjustments I made
4. What ended up working
5. Specific code/settings I'm using

## Solo Dev Reality Checks

### Replace "Players" with Reality:
- ❌ "Players are discovering secrets..."
- ✅ "Building a feature where players can discover secrets..."
- ✅ "Planning to add [feature] - testing how it works..."

### Replace "We/Team" with "I":
- ❌ "We implemented a system..."
- ✅ "I built [feature] using..."
- ✅ "Learning [concept] to add [feature]..."

### Replace "Community" with Development Phase:
- ❌ "Our community has created wikis..."
- ✅ "Still in development - hoping future players will..."
- ✅ "Designed this so players could eventually..."

### Be Honest About Budget/Learning:
- "Hired a contractor for art ($2,400 budget)"
- "Learning [X] on the fly as I build"
- "Solo dev means prioritizing - focusing on core features first"
- "This feature took longer than expected while learning Unity"

## Measurement & Iteration

Track what resonates:
- Helpful, specific posts perform well
- Before/after wins get engagement
- Honest learning process builds connection
- Practical examples drive blog traffic

## Voice Consistency Checklist

Before posting, ask:
- [ ] Does this sound helpful and collaborative?
- [ ] Did I share genuine learning or results?
- [ ] Are there concrete numbers/specifics?
- [ ] Did I use "I" and keep it authentic to solo dev?
- [ ] Would this help someone learning Unity?
- [ ] Is the tone positive and constructive?
